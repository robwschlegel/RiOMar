## 2026-09-25: Google Doc tables missing grid lines, Supplement numbering, and References section — all fixed

Three more Google-Doc-conversion gaps, found the same day as the justification fix below.

**Table grid lines.** All 7 tables share one docx style (`Table`, confirmed via `document.xml` — none override borders per-table), which had no `<w:tblBorders>` at all, matching the LaTeX source's booktabs styling (sparse horizontal rules, no vertical lines). Added `add_table_grid()` (same style-level pattern as `justify_body_text()`) to give the `Table` style a full single-line grid on all sides + interior, independent of the PDF/print version's booktabs styling.

**Supplement figure/table/section numbering.** Three separate bugs, one per numbering type:
- *Tables*: `resolve_figtab_crossrefs()` only ever checked for `\setcounter{figure}{0}` to detect where supplementary numbering starts — it never looked for the manuscript's parallel `\setcounter{table}{0}` (`manuscript.tex` line 397), so every supplementary table just continued the main-text numbering (`Table 3`, `4`, ... instead of `Table S1`, `S2`, ...). Figures were already correct. Fixed by tracking a separate `tab_reset_idx`, mirroring the existing figure logic.
- *Supplement subsection headings*: the Supplement's 6 subsections are titled `\subsection*{\thesuppsec. Title}`, where `\thesuppsec` is a custom counter (`\newcounter{suppsec}` + `\renewcommand{\thesuppsec}{S\arabic{suppsec}}`, incremented via `\refstepcounter{suppsec}` before each heading) — real LaTeX resolves this at compile time, but pandoc's reader has no concept of a macro it never defined, so the literal string passed through unresolved. Fixed with a new `resolve_suppsec_headings()` preprocessing step that strips the counter machinery and substitutes each `\thesuppsec` occurrence by hand, in source order (confirmed via grep: no `\ref{sec:s_*}` cross-references elsewhere need resolving too).

**References section: missing heading, wrong position.** Pandoc's citeproc always appends the generated bibliography at the very end of the document, regardless of where `\bibliography{}` sits in the LaTeX source — in `manuscript.tex` that's *before* `\appendix`, so the References section was landing after the entire Supplement, and with no heading at all (pandoc only adds one when `--metadata reference-section-title=<text>` is passed, which the pandoc call never did). Fixed two ways: added `--metadata reference-section-title=References` to the pandoc invocation (gives citeproc's output a heading, confirmed to render unnumbered like the manuscript's other `\section*{}` headings); and added a `mark_references_position()`/`move_references_before_supplement()` pair — the former replaces `\bibliographystyle{}`/`\bibliography{}` with a unique plain-text marker before pandoc runs, the latter (run immediately after pandoc, *before* `strip_internal_links()` since that deletes the bookmark it anchors on) cuts the citeproc-generated References heading + all 82 bibliography paragraphs from the document's end and splices them back in at the marker's original position.

Verified end-to-end on a full rebuild: `Table S1`–`S5` (was `Table 3`–`7`), Supplement headings read `S1.`–`S6.` with correct titles, References heading appears once, immediately before "Supplementary material", with all 82 bibliography entries immediately following it and nothing left dangling at the document's end. Zip integrity and XML well-formedness both check out; the earlier justification/table-grid fixes remain intact.
